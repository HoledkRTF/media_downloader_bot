## Recent Codenames
- **Anchor-Point** (v2.17.2): Pin deployment identity to the real host. The hardcoded fallback `RENDER_URL` pointed at the retired `media-downloader-bot-skg5.onrender.com` alias while the service's canonical host is `media-downloader-bot-2ia1.onrender.com`, so a missing `RENDER_EXTERNAL_URL` would have pointed the Telegram webhook at a dead host; the fallback now names the live service. `is_render` no longer treats `RENDER_SERVICE_ID` as a signal, because that variable is now kept in a developer's `.env` to query the Render API — with it set, any local run of `main()` took the webhook branch (local aiohttp server plus `set_webhook`) instead of polling. Runtime detection now keys off `RENDER`/`RENDER_EXTERNAL_URL`, which Render injects and a local `.env` does not.
- **Surge-Relay** (v2.17.1): Performance pass. GIF->MP4 encodes no longer run inside `GLOBAL_DOWNLOAD_SEMAPHORE`, where a 20-GIF catalogue spent minutes in ffmpeg holding one of four download slots and queueing every other user's fetch behind it; encoding now runs after the semaphore is released under its own `GIF_ENCODE_SEMAPHORE` (max 4 concurrent encodes, down from 8 in the old worst case). Stats, retry-queue and history writes (blocking Mongo or locked-file I/O) are offloaded to a worker thread instead of stalling the event loop mid-update, and the repeated `add_failed_download` + `record_download_history` pairs in the download path collapsed into one `_record_failure()` helper. A bookkeeping write that throws after a successful upload can no longer turn a delivered file into a "Telegram rejected the upload" error with a bogus /retry entry. `send_album` probes dimensions only for real video files instead of spawning an ffprobe per photo, tikwm clips stream to disk in 64KB chunks instead of being buffered whole in RAM, and `handle_replied_link` runs its retry-queue and history lookups concurrently.
- **Quicksilver** (v2.17.0): Reddit gallery animation fix. GIF catalogue items are full-size originals (often 10-45MB with no mp4 sibling), so conversion now preserves the source frame rate and resolution (capping only sources wider than 1080) and encodes at `veryfast`/crf 23 with a 180s budget instead of timing out on `faster` at crf 24, with a 720p `ultrafast` retry only if that overruns, the redundant second conversion pass in `send_album` is gone, gallery downloads stream to disk under a 120MB per-item cap rather than buffering entire catalogues into RAM, encodes run two at a time, and each album animation / media-group chunk uploads independently so one rejected file can no longer discard the rest of the catalogue. Failed downloads now report the reason in chat instead of silently deleting their status message, and externally hosted Reddit posts (RedGifs, Imgur, ...) are resolved through the post's Atom feed (`/comments/<id>.rss`), which still answers when Reddit's JSON API returns its datacenter "blocked" page and vxreddit only exposes a preview thumbnail. Item selections are parsed by `parse_media_indices`, which normalises commas, semicolons and ranges — previously only whitespace-separated numbers were recognised, so `3,4,6,7,8,11` was silently ignored and the whole 20-item catalogue was fetched instead of the requested six. The Twitter zero-bandwidth fast path no longer passes `supports_streaming` twice to `reply_video` (a `TypeError` that pushed every direct Twitter video into a full yt-dlp download) and no longer passes it to `reply_animation`, which PTB does not accept. Multi-link messages now keep each link's own item numbers and ranges (`linkA 1,3 linkB 2-4`) via `extract_link_selections`, instead of dropping every selection but the last when the message is split per link. Ported the rest of the v2.16.1 hardening from the code-review snapshot: per-request unique CBZ/EPUB filenames (a same-manga chapter re-download no longer overwrites or deletes a running build), `MAX_ARCHIVE_PAGES` (500) and `MAX_NOVEL_CHAPTERS` (2000) caps, the shared `GLOBAL_PAGE_FETCH_SEMAPHORE` (20) replacing the per-request 15/20 semaphores, `html.escape` on captions/search labels/log output, and a `cleanup_job` that returns early while `has_active_downloads()` so the sweep cannot delete files mid-download. The media pipeline is inside that guard too: `process_single_link` brackets the whole `_process_single_link_impl` call with `begin_download_activity()`/`end_download_activity()` in a `finally`, and `download_media` is only reached from inside it, so a slow gallery download or encode is never swept mid-flight.
- **Vanguard-Lock** (v2.16.0): Core logic and concurrency overhaul. Preserves failed batch downloads in `batch_downloader.py` so they are never prematurely marked complete, secures redownload buttons in `redl_callback` by restricting execution exclusively to the originating user, isolates Vault settings updates via user-scoped MongoDB `$set` updates and safe read failure handling to protect all users' settings, eliminates local JSON lost updates through cross-platform file locking (`file_lock`) combined with thread synchronization, bounds incoming webhook task queues to 25 with 429 backoff throttling to prevent memory exhaustion, and documents all environment variables in `.env.example`.
- **Bastion-Fortress** (v2.15.0): Comprehensive security, safety, and concurrency hardening. Sanitized all credentials across utility and archive scripts and tightened `.gitignore` exclusions. Locked administrative ingress by requiring `ADMIN_USER_IDS` authorization for `/adminmisuse` and the `/logs` Telegram command, and gated the web `/logs` endpoint behind admin token authentication. Protected `/clean` against deleting user messages by intercepting bot send methods to only purge verified bot responses. Prevented concurrent file write collisions by isolating yt-dlp downloads into unique subdirectories, capped playlists at 10 items/100MB with a global concurrency semaphore (4 workers), bounded webhook tasks with concurrency control, and converted all JSON persistence to atomic file replacements.
- **Citadel-Shield** (v2.14.0): Fixed multi-image Twitter album NameError crash (line 1255), resolved animation disk leak by mutating `files` in place in `send_album`, implemented `reply_animation` in `batch_downloader.py` proxy, reinforced webhook ingress with `X-Telegram-Bot-Api-Secret-Token` validation, dedicated bounded thread executor for heavy scrapers, offloaded blocking Gofile, ffprobe, and zip tasks to `asyncio.to_thread`, and protected user bookmarks from transient database read failures.
- **Aegis-Lock** (v2.13.0): Enforced concurrent in-flight download deduplication per user/URL, shielded external network calls (Reddit fallback, TikTok CDN, Gofile servers/uploads, Telegram profile photo API) with explicit timeouts, added MongoDB compound indexes (`(user_id, norm_key)`, `timestamp`, retry queue `user_id`), and applied selective query projections to download history lookups.
- **Vivid-Flow** (v2.12.0): UI/UX overhaul. Real-time Telegram chat action indicators (uploading video/photo/document), dynamic status message transitions with live multi-link batch counters, rich captions with platform/subreddit/handle badges and file sizes, and one-tap ❤️ Vault inline button on delivered media.
